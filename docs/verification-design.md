> 状态：**设计稿（未实施）**。按正本 §三-4 的排期，本稿先交栗子过目 → 写回正本 → 再动实现。
> 对应缺口清单 `B1`（P0）。本稿只回答四件事：**哪类内容算可求证**、**求证手段（本机可执行的判据）**、

## 一、判定：什么算"可求证"

**判据一句话**：一条内容算可求证，**当且仅当本机存在一个机械判据（不需要人、不需要模型）能把它判成
"对／不对／查不了"**。拿不出判据的，就是不可求证——**不可求证 ≠ 可疑**，它只是"本机判不了"。

按类型分：

| 类型 | 可求证性 | 本机判据（存在才叫可求证） |
|---|---|---|
| `resource`（路径／文档／工具／链接） | **全部可求证**（"它是资源"的定义就是"能指到一个东西"） | 路径存在性／文件非空；URL 合法性（`http(s)＋非环回／私有／保留`，已有 `validate_outbound_url`）；可选做一次外站探测（见 L3） |
| `status`（进行中／短时） | **可求证**（时间与进度自洽性） | 相对时间词 vs 记录时间戳（"昨天"vs `created_at`）；与同对象既有 status 的取值一致性；TTL 到期性 |
| `fact` | **分两类** | ① **可求证**：自带的路径／URL／数值／单位／日期（可机械校验的部分）；② **不可求证**：身份、履历、归属、他人行为（"我是班长""我在天大"）——本机没有权威数据源 |
| `preference`（价值判断） | **不可求证**（"我喜欢 X"没有真值可查） | 无（**求证机制不碰偏好**，偏好的冲突归确认轨） |

补充三条纪律：

1. **只对"内容里那部分可校验的结构"求证**，不对整句下判断：一句「我把导出写到 `D:/x/y.md` 了，
   用 Vim 写的」的可求证部分是路径，不是"用 Vim"。
2. **模型输出与用户输出同判据**（正本口径）：同一句"文件在 docs/README.md"，谁说的都按同一条判据判。
3. **不可求证内容直接存储**（正本 §三-3 定案）：记忆是"用户说过什么"的记录，不是知识库；
   不给不可求证内容打"可疑"标签，避免把人的自我陈述当成待审对象。

## 二、求证手段：三级，按成本从低到高

| 级 | 名称 | 判据 | 成本 | 默认 |
|---|---|---|---|---|
| **L1** | 存在性／自洽性 | 路径存在、文件非空、URL 合法（仅 http/https，拒环回／私有／保留）、数值区间与单位自洽、相对时间与时间戳自洽 | 零（纯本地、毫秒级） | **开** |
| **L2** | 库内一致性 | 与库里同对象的既有取值比对（复用既有 `conflict.detect_rule_conflicts`）：一致→加固（`verified`）；冲突→挂起确认（**已有路径**，不改语义） | 零 | **开** |
| **L3** | 外站探测（可选） | 对 `http(s)` 链接发一次 `GET`／`HEAD`（超时＋结果缓存；拒环回／私有／保留；只读、不落内容，只记状态码与标题摘要） | 一次网络往返；**会产生出站请求** | **默认关**（用户显式开 `verification_external` 才用） |

L3 的纪律：**出站只允许 http/https 且拒环回／私有／保留**（与本项目 A41 同口径）；失败（超时／403／403 类）
只记"未取证"，**绝不记成"假"**；同一 URL 在缓存窗口内不重复探测。

## 三、失败处理：三态，不是"存/不存"

| 判定 | 含义 | 处置（**按来源分流**） |
|---|---|---|
| `verified` | 判据通过 | 按类型直存，附 `verification_status=verified` ＋ 手段／时间／证据摘要（可审计） |
| `refuted` | 判据**明确否证**（路径不存在、数值自相矛盾、URL 非法） | **不进正式记忆**：<br>· 来源＝用户 → **挂起一次询问**（"你说的 X 我本机没找到：是笔误、还是指别的机器？"）＋ `candidate` 状态，TTL 7 天，**不静默丢**（用户可能是指另一台机器／未来会创建）<br>· 来源＝模型 → **丢弃** ＋ 写 `observe.jsonl`（模型幻觉；不打扰用户，符合"模型输出永不静默注入"） |
| `unverifiable` | 本机判不了（偏好、身份、履历、主观事实） | **直接存储**（正本口径），`verification_status=unverifiable`，不作为"可疑" |

为什么用户来源不直接丢：**否证的判据可能是判据自己的边界**（路径还没建、笔误、指别机）。
记忆层宁可问一次，也不替用户宣布"你说错了"。

## 四、与四类型／确认轨的交互

```
用户输出 ─┬─ preference ─────────────────────► 直存；冲突 → 确认轨（人工裁决）
          ├─ fact ─┬─ 含可校验结构 ─► L1/L2（refuted 走三态分流）
          │        └─ 不可求证     ─► 直存
          ├─ resource ─► L1（必有判据；L3 可选）
          └─ status   ─► L1（时间/进度自洽）＋生命周期 TTL
模型输出 ─┬─ 可求证（路径/URL/数值）─► 同判据；refuted → 丢弃＋观察日志
          └─ 不可求证 ──────────────► 观察轨（shadow=1，永不注入；经确认后晋升）
```

**两条边界（防越权）**：
- **求证不替代确认轨**：确认轨仍**只**服务偏好／变更类（栗子定案 1）；求证管"可机械判定的结构"。
  两者交集为空：**能机械判的不用问人，需要人拍板的机器判不了**。
- **求证不改变"记忆只增不删"**：`refuted` 的处置是"不进正式记忆"或"挂起为 candidate"，
  不删既有记忆；已有记忆被新证据否证时，走既有的 `supersede`／挂起链路。

## 五、实现映射（拍板后照此施工）

1. 新模块 `src/hippocampus/memory/verification.py`：
   - `classify(content, kind) -> {"verifiable": bool, "checks": [L1 判据名…]}`
   - `verify(content, kind, *, conn=None, source="user", external=False) -> VerificationResult`
     （`status` / `method` / `evidence` / `checked_at`；**纯机械、零模型**）
2. 插入点：`MemoryCore.write()` 的安全守卫之后、去重之前；`consolidate` 的模型输出分支
   （把既有"幻觉资源不入库"的路径存在性判据收敛到统一入口，行为不回归）。
3. Schema：`memories` 追加四列（带默认值，符合 v1"只追加"契约）：
   `verification_status TEXT DEFAULT 'unverifiable'`／`verification_method TEXT DEFAULT ''`／
   `verified_at INTEGER DEFAULT 0`／`verification_evidence TEXT DEFAULT ''`。
4. 开关（活跃参数，可人工标定）：`verification_enabled`（默认 **on**，只跑 L1+L2）、
   `verification_external`（默认 **off**，开才走 L3）。
5. 观测：`observe.jsonl` 增 `verification` 事件；`explain` 显示"这条为什么被否证／为什么直存"。
6. 验收锚点（新增 A42–A45，写回正本 §七）：
   - **A42** 路径不存在的模型资源 → 丢弃（不注入、不入正式记忆，观察日志有痕）；
   - **A43** 路径不存在的用户资源 → 挂起一次询问，**不静默丢**；裁决后按用户选择落库；
   - **A44** 不可求证内容（"我是班长"）**直接存储**，且**不带**"可疑"标记；
   - **A45** L3 关闭时**零出站请求**（测试用 monkeypatch 断言没有网络调用）。

## 六、明确不做（防以后被当缺口）

- 不做"事实正确性"承诺（求证只做本机判据；不引入外部知识库／搜索引擎）；
- 不对偏好求证（价值判断没有真值）；
- 不用模型做求证（判据必须机械、可复跑；模型参与就不可复跑）；
- 不把 `unverifiable` 记成"可疑"（那是安全守卫的 `security_flag` 的职责，两者不要混）。
